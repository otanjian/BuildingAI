# Design: Rebrand User-Visible App Name to Bowi AI

## Context

The product name "BuildingAI" is hardcoded in user-visible strings across the monorepo:
web metadata, PWA manifest, Tauri config, React copy, NestJS API defaults/descriptions, CLI
output, and docker-compose logs. There is no central brand constant — each surface carries
its own literal. See `proposal.md` for the full scope table.

Key constraint: the rebrand must touch only **user-visible** strings and comments.
Internal identifiers (`@buildingai/*` packages, storage keys, Tauri bundle id, JWT dev
secret, GitHub URLs, LICENSE legal texts) stay untouched to avoid breaking the monorepo,
existing installs, auth tokens, and external links.

## Goals / Non-Goals

**Goals:**
- Replace every user-visible "BuildingAI" with "Bowi AI" in the listed surfaces.
- Also update developer-facing comments that name the product (low-risk hygiene).
- Keep the exact casing "Bowi AI" (capital B, space, capital AI) consistent.

**Non-Goals:**
- No renaming of `@buildingai/*` packages, workspace package names, or imports.
- No changes to localStorage keys, JWT dev secret values, Tauri bundle identifier,
  Cargo crate names, GitHub repository links, or extension LICENSE texts.
- No touching built artifacts (`public/web/*`, `packages/api/public/web/*`) — they are
  regenerated by the release pipeline.
- No logo/icon artwork changes (user said icon is already suitable).

## Decisions

**D1: Direct literal replacement per file (no shared constant introduced).**
The affected strings live in heterogeneous files (HTML meta, JSON manifest, Tauri config,
React TSX, NestJS TS, JS CLI script, YAML compose). Introducing a central brand constant
would require build-time injection in every surface — disproportionate for a one-off
rename. Simple literal edits are the smallest, most reviewable change.
- *Alternative considered:* Vite `define` for client + env-driven title. Rejected: manifest.json
  and tauri.conf.json are static files that would need templating for marginal benefit.

**D2: "BuildingAI" → "Bowi AI" as exact string replacement in scoped files.**
Only the exact user-visible/product-name occurrences are replaced. Mixed-case technical
identifiers (e.g. `buildingai-client-theme`) are excluded by leaving their files untouched
where they also carry non-brand content (index.html stores keys).
- *Alternative considered:* blanket `sed` across repo. Rejected: would hit B-class
  identifiers (packages, JWT, links) — high risk.

**D3: Chinese copy keeps its language wrapper, only the brand token changes.**
Strings like `关于BuildingAI` → `关于Bowi AI`, `您现在可以开始使用 BuildingAI 了` →
`您现在可以开始使用 Bowi AI 了`. Brand token is substituted, surrounding text unchanged.

## Risks / Trade-offs

- [Desktop installs lose old product name] → Mitigation: `productName` change is expected
  during a rebrand; bundle id stays stable so app identity/data is preserved.
- [Missed user-visible occurrence after this pass] → Mitigation: final verification greps
  `BuildingAI` across `packages/client/src`, `packages/api/src`, `packages/cli`, and
  `docker-compose.yml`; remaining hits must be B-class (excluded) — confirmed one-by-one.
- [Casing inconsistency "Bowi AI" vs "BowiAI"] → Mitigation: use "Bowi AI" (with space)
  everywhere; verification greps for `Bowi` variants to confirm uniform casing.
- [PWA name mismatch after deploy until rebuild] → Mitigation: release pipeline
  (`build:web` + `scripts/release.mjs`) regenerates `public/web`; no manual artifact edits.
