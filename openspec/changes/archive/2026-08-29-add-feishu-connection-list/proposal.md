## Why

当前“飞书机器人”菜单进入的是单个配置表单，并且一个智能体只能保存一条飞书配置。随着一个智能体需要服务多个企业、测试环境或不同业务群，管理员无法在不覆盖旧配置的情况下接入多个飞书 App。

**Why now:** 现有飞书通道已支持标准智能体并具备独立长连接能力；现在应将控制台入口升级为连接列表，避免继续扩大单配置模型的迁移成本。

## What Changes

- 点击“飞书机器人”进入飞书连接列表，展示连接名称、关联智能体、App ID（脱敏）、启用状态、运行状态和最近错误。
- 支持新增、编辑、测试、启用/停用和删除飞书连接；同一智能体可关联多个飞书 App。
- 每条连接使用独立连接 ID，拥有独立凭证、运行实例、会话上下文和事件幂等状态。
- 同一个飞书 App ID 全局只能绑定一个智能体，保存时给出明确冲突提示。
- 将连接元数据和凭证迁移到专用连接存储，并保留现有按智能体保存的配置作为可回滚的迁移来源；迁移期间不丢失已启用连接和历史会话。
- 编辑连接时不回显 App Secret 或智能体 Token；删除前二次确认，删除后停止运行连接并清理该连接的运行态数据。
- 在多 API 实例部署下确保同一个连接最多由一个实例持有飞书长连接租约。

## Non-goals

- 本期不支持一个飞书 App 将消息动态路由到多个智能体。
- 本期不引入飞书以外的新渠道，也不重做现有飞书消息卡片能力。
- 本期不改变智能体自身的发布、权限和计费规则。
- 本期不提供历史消息迁移或跨连接合并会话。

## Capabilities

### New Capabilities

- `feishu-connection-management`: 管理多条飞书连接及其列表、生命周期、唯一绑定和迁移行为。

### Modified Capabilities

无。现有飞书通道实现尚未归档为根级 OpenSpec capability，本变更通过新 capability 约束其升级行为。

## Impact

- NestJS 飞书通道服务、控制器、DTO、运行时连接和 Redis key。
- React 控制台飞书菜单页面、列表/表单路由、服务 hooks 和权限按钮。
- PostgreSQL 飞书连接表及唯一索引、凭证加密配置和现有 Dict 配置的兼容迁移。
- 需要补充后端服务测试、并发/租约测试、前端交互测试、迁移验证和多连接手工冒烟测试。
