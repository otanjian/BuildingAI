## Context

飞书控制台同时保留了按 Agent ID 的旧接口和按 connection ID 的新接口。新测试入口已经能解析连接中的加密凭证，但随后调用旧测试入口；旧入口发现连接存在后又调用新入口，形成异步递归。旧入口中的外部 `fetch` 也没有超时。

## Goals / Non-Goals

**Goals:**

- 将凭证解析、校验和飞书鉴权收敛到一个不会回调控制器入口的内部路径。
- 让外部鉴权在有限时间内成功或失败，并保持已保存数据只读。
- 用单元测试锁定递归修复和超时行为。

**Non-Goals:**

- 不删除旧版接口或 Dict 兼容读取能力。
- 不改变连接启动、租约、消息处理和凭证加密协议。

## Decisions

- 在 `testConnection` 中完成解析后的 DTO 校验和飞书鉴权；旧 `test` 入口仅负责旧接口的配置读取，不能在新连接存在时互相调用。
- 使用 `AbortController` 为鉴权 `fetch` 设置固定超时，并将超时转换为不泄露密钥的业务错误。固定边界优于让 Node/网络默认行为决定等待时长。
- 测试请求只读取已保存凭证，不写入连接、不启用连接；保留现有成功/失败响应契约。

## Risks / Trade-offs

- 网络较慢但最终可用的飞书环境可能被判定为超时；有限失败边界是避免控制台和 API 线程无限占用所必需的，管理员可重试。
- 不同 Node 版本对 `fetch` 的 abort 错误类型可能不同；测试应验证稳定的业务错误消息而非底层异常类。
